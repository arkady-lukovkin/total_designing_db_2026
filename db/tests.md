# Протокол проверки FoodExpress

Ручные SQL-операции от 10 ноября 2026. PostgreSQL 15.19, схема `lukovkin_food`, пользователь `inspector`, часовой пояс Europe/Moscow. Для конкурентных изменений использовались отдельные SQL-сессии.

| Операция | Наблюдаемый результат |
|---|---|
| Установка файлов `00`–`09` и выдача прав | 12 физических таблиц, 8 ENUM-типов, 15 пользовательских триггеров, 4 представления |
| Хранение денежных полей | В `order_core` есть только order_amount; commission/total_amount вычисляются в `"order"`; amount отсутствует в payment_core и доступен в payment |
| Создание заказа через `"order"` и оплаты через `payment` | Работают DEFAULT UUID/времени и RETURNING; для суммы блюд 1000 получены комиссия 100 и итог/оплата 1100 |
| Исправление суммы заказа и исторической цены | После согласованного изменения до 2000 комиссия равна 200, итог и сумма оплаты — 2200 |
| Неверная сумма оплаты и явный NULL идентификатора | Отклонены с `23514` и `23502` соответственно |
| UPDATE/DELETE попытки оплаты через представление | Выполняются, RETURNING возвращает фактические значения |
| Конкурентные UPDATE одной оплаты | Устаревшая операция получила `40001`; повтор сохранил ранее изменённый статус |
| `add_product(...)` | Блюдо создано с UUID и начальным NULL-рейтингом |
| Прямые неверные рейтинги | INSERT блюда с рейтингом 5 без отзывов и UPDATE рейтингов блюда/ресторана отклонены с `23514` |
| Изменение отзывов | Рейтинг 4 изменился на 2; перенос отзыва пересчитал ресторан и вернул NULL блюду без отзывов; удаление выполнено |
| Флаг генератора | Изменение отзыва с `lukovkin_food.generating = on` и устаревшим рейтингом отклонено на COMMIT с `23514` |
| Конкурентный пакет и старый снимок REPEATABLE READ | Добавление оценок 1 и 5 при прежнем среднем 3 сменило версию родителя; старая транзакция получила `40001`, рейтинг остался 3 |
| `TRUNCATE review` | У всех блюд и ресторанов рейтинг стал NULL |
| Повторное заполнение после восстановления | Вызовы с 10 и 1 дали 55 заказов/оплат и 11 строк статистики |
| `courier_salary()` и `how_much_money` | Расчёт выполнен; на большом пакете денежный отчёт вернул шесть месяцев |
| `erase_test_data()` | Два последовательных вызова выполнились; архив восстановлен с нулём строк во всех 12 таблицах |
| Восстановление архива | Выполнено в отдельной базе с подготовленной exts; процедуры и защита рейтингов работают под inspector |

## Объём данных

Ручной вызов `insert_test_data(10000)` с COMMIT занял 35.096 секунды в среде с 2 CPU и 1.5 GiB RAM. Созданы 10 000 клиентов, курьеров, ресторанов и категорий; по 50 000 адресов, связей клиент–адрес, блюд, заказов, отзывов и оплат; 150 289 позиций и 60 000 строк истории выплат. Всего — 550 289 строк.

Прочитанные счётчики расхождений рейтингов блюд, рейтингов ресторанов и сумм заказов с позициями равны нулю. `get_statistic()` вернул 10 000 строк, денежный отчёт — месяцы с июня по ноябрь 2026. Это результаты указанного случайного пакета, не гарантия времени для другой среды.

## Резервная копия

`foodexpress_lukovkin.backup` создан через `pg_dump -Fc --schema=lukovkin_food --no-owner --no-acl`. Размер — 89 109 байт. SHA-256: `9ee3cfe89d264aabe2d3d03cc4e4975112feffbb1814e69e0ea0a6cb6f89ec5a`.

Архив содержит схему с пустыми таблицами. Схема exts и расширение uuid-ossp подготавливаются отдельно. Порядок установки и восстановления приведён в `README.md`; обоснование 3НФ и ограничения совместимых представлений — в `constraints.md`.
